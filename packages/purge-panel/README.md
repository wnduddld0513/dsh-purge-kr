# Purge UI

독립된 DSH 데스크톱 UI 플러그인이다. 공식 `dsh-purge` 가 기능과 데이터 인터페이스를 제공하고, `dsh-purge-panel` 이 오른쪽 진입점, 설정 레이아웃, 플러그인 생명주기가 관리하는 옛 진입점 숨김 스타일을 제공한다. 공식 패키지에 쓰지 않고, 백엔드 패치를 복사하지 않으며, 세션 훅을 설치하지 않고, 패치를 자동 적용하거나 복원하지도 않는다.

## 사용

먼저 공식 dsh-purge 를 설치하고 활성화한 뒤 이 패키지를 설치한다. 오른쪽 사이드바의 "+ → Purge" 로 설정을 연다. 이 플러그인의 설정 진입점에서 열 수도 있다.

두 플러그인은 따로 업데이트된다. 공식 Purge 를 업데이트해도 이 패키지의 UI 파일은 교체되지 않는다. 이 플러그인을 비활성화하면 공식 원래 진입점이 다시 나타나고, 공식 설정과 데이터는 삭제되지 않는다. 마이그레이션 전의 `dsh-purge@1.1.71-local.*` 는 옛 내장 UI 버전이므로, 오른쪽 탭이 중복 등록되지 않도록 먼저 공식 원본으로 되돌린다.

## 호환 범위

DSH 데스크톱 현재 설치 환경과 공식 Purge 1.1.71 에서 실측했다. UI 는 `/dsh-purge/*`, 옛 드릴 콘솔 `/redteam/api` 를 통해 기존 인터페이스를 사용한다. 서비스를 쓸 수 없거나 버전이 검증되지 않은 경우에는 안내를 표시한다. 공식이 향후 인터페이스나 진입점 class 이름을 바꾸면 이 플러그인에 적응이 필요할 수 있고, 영구 호환을 약속하지 않는다.

옛 진입점 숨김은 `.dshp-launch`, `.dshp-hero-chip`, `.dshp-tab-chip`, `.dshp-dock` 네 개의 CSS 선택자만 사용한다. 스타일은 플러그인 로드 생명주기가 문서 head 에 직접 붙이며, 설정 페이지나 shell.overlay 의 렌더 여부에 의존하지 않는다. 플러그인을 비활성화하면 자신이 만든 스타일 노드만 정리한다. 전역 DOM 스캔, 몽키 패치, 로더 하이재킹, 공식 설치 파일 재작성은 없다. 공식 자체의 숨김 컴포넌트와 스캔 로직은 여전히 공식이 실행하며, 독립 UI 는 공식 구현을 침범하지 않고서는 그것들을 없앨 수 없다.

UI 는 독립된 `dshpp-` 클래스 이름과 locale 네임스페이스를 써서 공식 CSS 업데이트가 스타일을 덮지 않게 한다. 분류를 전환해도 저장하지 않은 초안이 유지되고, 상태를 새로 고쳐도 초안을 다시 쓰지 않는다. 방문한 분류는 마운트 상태를 유지한다.

## 출처와 유지보수

UI 부분은 YuJunZhiXue/dsh-purge 1.1.71 에서 파생되었고 저작권은 원저자에게 있으며, MIT 라이선스는 LICENSE 를 참고한다. 독립 UI 는 공식 릴리스가 아니다. 로컬 적응은 표시와 진입점만 조정하고, 프롬프트·보안 정책·모델 동작·백엔드 기능은 바꾸지 않는다.

현재 독립 버전: 1.1.2. 소스는 src/ 에 있고, client.js 는 자동 생성되는 설치 산출물이라 직접 편집하지 않는다. index.js 는 부작용 없는 호스트 진입점이고, cordis.patch.yml 은 이 플러그인 자신만 등록한다.

## 1.0.1 수정

- 최초 읽기가 끝나기 전에는 편집을 막아, 느린 응답이 방금 입력한 내용을 덮지 않게 한다.
- 저장 중 새 입력은 저장하지 않은 초안으로 남기고, 옛 저장 응답이 그것을 덮지 않는다. 반복 저장은 한 번의 요청으로 합친다.
- 텍스트 저장은 타임아웃과 HTTP 상태 검사를 공통으로 적용하고, 실패하면 내용을 남긴 채 저장 버튼을 되돌린다.
- 호환 안내는 상태 페이지 데이터를 재사용하고 새로 고칠 때 함께 갱신해, 상태 요청이 중복되지 않게 한다.
- 승인 상태 동기화를 플러그인 생명주기에 포함하고, 비활성화할 때 재시도를 정리한다.
- 비동기 경합, HTTP 500, 타임아웃 복구, 모듈 로드 무부작용 테스트를 추가했다.

이번 라운드는 업스트림 패치, 드릴 콘솔, 모든 서드파티 의존성에 대한 전면 보안 감사가 아니다. 향후 업스트림 API 와 진입점 선택자 변경에는 여전히 적응이 필요하다.

## 1.1.0 모듈화

- `src/entry.js`: DSH 등록과 생명주기.
- `src/api/`: 요청, 타임아웃, HTTP 오류, 옛 라우트 호환.
- `src/state/`: 사이드바 상태, 승인 읽기, 현재 워크스페이스의 읽기 전용 구독.
- `src/components/`: 설정 페이지, 규칙, 스킬, 상태, 대화상자.
- `src/shared/`: 언어, 버전 판정, 공용 React 내보내기.
- `src/styles/`: 바로 편집할 수 있는 CSS.
- `src/vendor/drill.js`: 보존된 업스트림 드릴 콘솔로, 모듈만 격리했다. 기능 감사가 끝났다는 뜻은 아니다.

독립 UI 에서 쓰지 않던 옛 폴백·이어쓰기, 플로팅 창 위치, 전송 위젯 사본과 그 스타일을 정리했다. 공식 플러그인의 기존 동작은 바뀌지 않았다. 규칙 페이지는 현재 세션 디렉터리를 직접 읽고, 세션을 전환하면 새로 고쳐지며, 늦게 도착한 옛 요청이 새 상태를 덮지 않는다. 스킬 인터페이스는 404/405 일 때만 옛 라우트로 폴백하고, 500 이나 형식 오류일 때는 이미 실행되었을 수 있는 쓰기를 다시 보내지 않는다.

개발 시 `npm ci --ignore-scripts --legacy-peer-deps`, `npm run build`, `npm test` 를 실행한다. CI 는 소스와 커밋된 빌드 산출물이 일치하는지 검사하고, 테스트는 실제 설정을 바꾸지 않는다. 소스 모듈화가 업스트림 전체에 결함이 없다는 뜻은 아니며, 이후 모듈별로 항목을 검증한다.

## 1.1.2 수정

옛 진입점 숨김 스타일이 더 이상 shell.overlay 안의 React style 노드에 의존하지 않는다. 페이지를 닫거나 전환해 overlay 가 렌더되지 않아도 옛 플로팅 버튼과 옛 패널은 계속 숨겨지고, 이 UI 플러그인을 중지하면 생명주기에 따라 복원된다. 회귀 테스트는 overlay 가 전혀 렌더되지 않는 경우, 마운트 후 언마운트, 플러그인 정리를 모두 다루며, 공식 플러그인 파일·프롬프트·개인 설정은 건드리지 않는다.
