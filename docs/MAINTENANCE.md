# 유지보수, 마이그레이션 및 복구

현재 버전 **1.6.101**. 패키지 이름은 `dsh-purge-community`이며, 배포 출처는 이 저장소의 정식 GitHub Releases 뿐이다; 내부 Cordis ID `dsh-purge`, HTTP `/dsh-purge/*` 및 사용자 데이터 디렉터리는 유지한다. 주요 설치 단계와 미러 장애 결정 트리는 [설치 안내](INSTALLATION.md)에 통합되어 있다; [AGENTS.md](../AGENTS.md)는 Agent 운영 설명서다.

## 호환과 운영 경계

검증된 호스트 대상은 Desktop 0.2.1-rc.1 / rc.2 이다. 호스트 레이아웃이 없으면 쓰기를 중단한다; 다른 버전은 미검증으로 표시하며, 컴포넌트 버전 불일치는 보고만 한다. 호환 상태는 "전체 패치 적용 완료"의 보장이 아니므로 selfcheck/diagnose 로 항목별로 확인한다. 설치기가 Windows 진입점을 지원한다는 것이 Windows 패치/UI 전체 검수를 마쳤다는 뜻은 아니다.

설치/업데이트, 호스트 패치 적용, 재시작은 각각 독립된 동작이다. 설치 전에 백업하고 호스트 패치 적용 전에도 백업한다; 설치가 성공했다고 자동 적용되거나 자동 재시작되지 않는다. 업데이트 확인과 자동 설치는 따로 설정하며, 기본값은 확인 켜짐·설치 꺼짐이고 기존 선호는 계속 유지한다.

## 스냅샷

경로는 `$DSH_HOME/dsh-purge-community/backups/<id>/manifest.json` 이며, 무결성 매니페스트에 SHA256 과 원래 profile, Purge bundle 을 담는다; 대용량 파일의 내용 주소 중복 제거는 `objects/` 에 있다. 기본 보존은 최근 5개, 하루 1개씩 총 7일, 200MB 상한이며, 현재 작업 스냅샷은 보호된다. 유지보수 잠금이 동시 실행을 막는다; 비정상 종료로 남은 잠금은 유지보수 프로세스가 없는지 먼저 확인해야 하며 무작정 잠금을 삭제하지 않는다.

설치된 Purge 패키지, profile 의 package.json/cordis.patch.yml/pnpm-lock.yaml, Purge 상태, prompt-inject.md, 규칙을 포함한다. 별도 자격 증명, 세션, Qwen 그림 라이브러리/모델을 추가로 스캔하지 않는다. profile 자체에 사설 연결 정보가 있을 수 있으므로 **백업 전체를 공개하지 않는다**.

## 실패 복구

다운로드/검증 실패는 마이그레이션에 진입하지 않는다; 마이그레이션이 시작되면 먼저 스냅샷을 뜨고 설치한다. 설치 패키지는 영구 pkgs 디렉터리로 복사해 file: 의존성이 임시 다운로드를 가리키지 않게 한다. 실패하면 백업 ID 를 반환한다; 원래 package.json 은 다른 의존성의 동시 변경이 없을 때만 복원하며, node_modules/잠금 파일 전체가 원자적으로 롤백되었다고 주장하지 않는다. 실제 상태를 확인한 뒤 롤백으로 넘어간다.

롤백은 먼저 스냅샷을 검증하고 현재 상태를 백업하며, 현재 인스턴스의 DSH CLI 로 스냅샷 코드를 설치하고, Purge 활성화 진입점만 복원하고 지금의 프롬프트, 규칙, 다른 플러그인 설정은 보존한다. 사용자 내용을 되찾으려면 스냅샷에서 파일 단위로 직접 선택한다; profile 을 통째로 덮어쓰지 않는다. 설치기가 실패한 원래 잠금 파일은 대조용으로 남길 수 있지만, 다른 플러그인의 새 변경을 덮어쓸 수는 없다.

```sh
purge-community backup
purge-community rollback <backup-id>
# 설치된 플러그인을 로드할 수 없을 때는 별도로 검증한 릴리스 패키지 CLI 를 쓴다:
# PURGE_DSH_CLI / DSH_HOME / DSH_PROFILE 을 설정한 뒤 실행
node package/bin/community.js rollback <backup-id>
```

profile 이 없거나 여러 개인데 명확히 선택되지 않았으면 중단한다. Web/Headless 는 현재 서비스 CLI 만 쓴다; [인스턴스 위치 확인](WEB-MAINTENANCE.md)을 본다. 다른 데스크톱 설치를 스캔해 잘못 건드리지 않는다.

## 미러와 업데이트

독립 마이그레이터는 issue #7 의 명확한 공개 패키지 버전 누락 오류에 대해서만 scoped 공식 소스 재시도를 한 번 수행한다. 공식 메타데이터 불완전, 사설/미지 소스, 실제 배포 시각/무결성/신뢰 실패는 모두 중단한다. 설치 실패 로그는 원래 오류를 보존하며, 잠금 파일을 지우거나 전역 캐시를 비우거나 검증을 끄거나 전역 소스를 바꾸지 않는다. DSH 마켓 설치는 플러그인 로드보다 앞서므로 공식 소스를 고르거나 독립 진입점을 써야 한다.

## 릴리스 제약

package.json, release-notes, README.md(영문), AGENTS.md, 유지보수·설치 문서의 현재 버전을 동기화한다. `npm run check:docs` 는 문서 버전과 핵심 설치 경계를 검사한다. CI 는 기능/패키징 회귀와 세 운영체제의 설치기 테스트를 실행하고, Windows 진입점은 PowerShell 5.1/7 을 함께 돌린다; 통과하면 tag 로 tgz, 안정 별칭, SHA256 을 릴리스한다. 마켓 인덱스는 정식 release 를 따른다. 실제 호스트 검수와 시뮬레이션 테스트는 따로 보고하며, 미지 플랫폼을 검증 완료로 쓰지 않는다.

## Windows 패키지 교체 상태와 오프라인 복구(issue #10)

1.6.26 부터는 타이머로 백그라운드를 종료하거나 데스크톱 셸을 죽여 패키지를 교체하지 않는다. 사용자가 "적용"을 누르면 도우미가 같은 설치 경로의 모든 DSH 프로세스 종료를 기다리고, 유일한 원본 아카이브 백업을 저장하고, SHA256 을 검증한 뒤 멈춘다; 사용자가 직접 연다. 실행 중인 다른 설치는 영향을 받지 않는다. 대기 중에 공식 업데이트가 아카이브를 교체하면 오류를 내고 새 아카이브를 보존하며, 새 버전에 다시 적용해야 한다.

진단 정보는 `resources/app.asar.purge-handoff.json` 와 `.json.log` 에 있다. `starting` 은 준비 완료가 아니고, `waiting_for_quit` 은 완료가 아니며, 디스크 패치 수는 현재 프로세스에 로드되었다는 뜻이 아니다. 도우미가 준비를 확인하지 못했거나 조기에 끝났거나 타임아웃되면 호스트는 계속 실행 상태로 둔다. pending 표식만 지우고 고쳤다고 선언하지 말고, 오류를 덮으려고 백신을 끄거나 권한을 전역으로 조정하거나 호스트 크래시 안내를 고치지 않는다.

기동 오류는 `.json.broker.log`, `.json.launch.log`, `.json.launch.log.error` 도 함께 본다. 실기에서 Electron 의 detached PowerShell 이 스크립트를 실행하지 않고 0 으로 종료되는 사례가 확인되어, 짧은 broker 로 독립 도우미를 기동한다. broker 성공이 핸드셰이크 성공을 뜻하지는 않으며, 최종 판단은 상태 파일로 한다. 유지보수 회귀에는 실제 Electron 이 필요하고, 기동 프로세스가 종료된 뒤에도 아카이브 교체가 끝날 때까지 도우미가 살아 있는지 검증해야 한다.

도우미가 끝내 완료되지 않을 때: 먼저 로그를 보존하고, 시스템 트레이에서 DSH 를 완전히 종료한 뒤 작업 관리자에 **해당 설치 경로**의 프로세스가 없는지 확인한다. 이번 "적용"이 이미 성공했고 `resources/app/package.json` 과 호스트 파일이 온전할 때만, 별도 PowerShell 에서 `resources/app.asar` 를 **이름을 바꿔 보존**한 새 타임스탬프 `.bak` 로 만들고 DSH 를 직접 연다. 이것이 우회하는 것은 실패한 핸드오프 프로세스이지 패치 재작성이 아니다. 파일이 여전히 점유 중이거나 권한이 부족하면 원본을 유지하고 중단한다; app.asar 를 삭제하거나 모든 Electron 을 강제 종료하지 않는다. 이 단계는 방금 공식 업데이트로 교체된 새 아카이브에는 적용할 수 없다.

원래 호스트로 돌아가기: 완전히 종료한 뒤 상태 파일에 기록된 `backup` 과 `archive_sha256` 을 대조하고, `Get-FileHash -Algorithm SHA256` 으로 해당 원본 아카이브 백업을 검증해 공식 버전을 넘나들지 않았는지 확인한다. 현재 언팩 디렉터리와 현존 아카이브를 보존한 다음 원본 백업을 `resources/app.asar` 로 복사하고 직접 연다. 이 과정은 profile 을 복원하지 않고 현재 프롬프트, 규칙, 다른 플러그인 설정을 덮어쓰지 않는다. 플러그인 버전 롤백은 앞의 `rollback <id>` 를 그대로 쓰며, 두 가지 롤백을 혼동하지 않는다.

## 네이티브 설정 인터페이스와 #42 마이그레이션(issue #9)

새 버전은 네이티브 `describe` / `replace` 가 있는 호스트에는 설정 업데이트 이벤트만 보완하고 혼합 API 를 만들지 않는다. 이미 주입된 정확한 옛 버전 legacy shim 은 다음 "적용"에서 제거되며, 수동으로 종료 후 재실행해야 효력이 있다. 사용자의 entry Config, settings.yaml/imported/legacy 문서는 모두 보존한다; 이번 수정은 과거에 잘못된 저장소에 기록된 데이터를 조용히 병합하지 않는다. 다른 플러그인이 이전에 옛 문서에 데이터를 기록했다면 먼저 백업하고 사용자가 선택적으로 마이그레이션한다. 미지의 서드파티가 고쳐 쓴 shim 은 적용을 중단하고 원본 파일, 백업, 진단을 보존한다.

## 언팩 후 pnpm 경로 누락

1.6.9 프리릴리스 후 Windows 상대 junction 이 기동 디렉터리에 따라 잘못 가리키는 문제가 발견되었다. 1.6.26 은 절대 대상을 쓰고, 설치 전에 현재 인스턴스의 링크를 수리하며, 옛 잘못된 링크는 이름을 바꿔 보존한다. 옛 업데이터가 이미 pnpm.mjs 가 없다고 보고했다면 독립 설치 진입점으로 1.6.26 을 고정 설치한다; app/runtime 디렉터리 내용을 삭제하거나 잠금 파일을 직접 비우지 않는다. 패키지 교체 전에 런타임을 쓸 수 없으면 원본 아카이브를 보존한다.

## 명령 이름 충돌, 인터페이스 404, 자체 점검 노란 항목(1.6.26)

#12 의 작성자가 최초 추정을 정정했다: 실측된 중단 지점은 `/rewind` 이름 충돌이며 inactive context 가 아니다. 새 버전은 명령의 원래 소유자를 유지하고 대체 명령으로 Purge 기능을 계속 제공한다. 다른 플러그인을 제거하거나 프로세스 수준 폴링을 추가할 필요가 없다.

#15 는 파일 원값과 유효값을 혼동했다. 새 버전은 `inferred`, `unknown`, `broken` 을 구분한다; 패널의 물음표가 증거와 범위를 보여준다. CLI 는 설정 표현식을 실행하지 않고 다른 설치를 스캔해 현재 인스턴스를 추측하지 않는다. AGENTS §16 을 본다; 사용자 권한을 자동으로 바꾸지 않는다.
## 프리셋 마이그레이션과 롤백(1.6.26)

`tool-subagent: toolFilter is no longer supported` 는 프리셋 활성화 호환 문제이며, 권한 자체 점검이나 "YAML 이 파싱된다"로 검수를 대신할 수 없다. 새 버전은 등록 전에 표현 가능한 옛 spawn deny 정책을 네이티브 하위 프리셋으로 변환하고 사용자 원본 파일은 건드리지 않는다. 백업은 `$DSH_HOME/dsh-purge-community/preset-migrations/` 에 있으며 각각 SHA256 매니페스트를 가진다; 백업 권한이 없거나 기존 스냅샷이 손상되었으면 중단한다.

빨간 표시를 없애려고 `preset install --force` 로 사용자 정의 파일을 덮어쓰지 말고, `toolFilter` 만 삭제하지도 않는다. 상위 세션은 도구가 완전하고 하위 세션은 원래 도구를 계속 제외하며, 깊이, 페르소나, 설정은 유지된다. 현재는 단일 spawn deny 목록만 지원하므로 미지 도구/기존 agentPreset/allow/다중 정책은 별도 설계가 필요하고 자동 추측할 수 없다.

현재 Desktop 의 실제 Electron 으로 `test/desktop-presets.mjs` 를 실행해 원 오류 재현, 실제 상위/하위 Agent 도구 목록, 반복 로드, 언로드, 백업 바이트 검증을 확인한다. 이 테스트는 격리된 home 에 빈 Agent 를 만들고 모델 요청을 보내지 않는다. 코드 롤백은 런타임 변환을 철회하며 사용자 파일을 덮어쓸 필요가 없다; 옛 버전을 다시 로드하면 새 호스트의 옛 인자 오류도 다시 만난다. 사용자 앱을 자동 재시작하지 않는다.


## 1.6.26 권한 복구와 읽기 전용 진단

[#20](https://github.com/wnduddld0513/dsh-purge-kr/issues/20) 의 원자 교체가 실행 비트를 잃던 문제를 수정했다. CLI 백업이 실패하면 쓰기를 중단하고 옛 백업은 보존한다. 런처를 롤백할 때는 내용과 일반 rwx 권한을 함께 복원해야 하며 텍스트만 복사하면 안 된다. 백업은 같은 디렉터리의 `.dsh-purge.bak` 이다; 백업이 이미 손상된 권한의 버전에서 나왔다면 올바른 실행 비트를 가진다고 가정할 수 없다. 앱 전체에 재귀 chmod 를 하지 말고, 런처를 고치려고 호스트 패치를 적용하거나 앱을 재시작하지 않는다.

[#19](https://github.com/wnduddld0513/dsh-purge-kr/issues/19) 는 여전히 조사 중이다. `purge-community host-status` 또는 상태 인터페이스 `host_layout` 로 디스크 레이아웃과 현재 서비스 진입점을 각각 대조한다. 디스크에 app.asar 가 있다는 것만으로 현재 서비스가 아카이브에서 로드되었다고 증명되지 않고, 아카이브가 옮겨졌다는 것만으로 옛 프로세스가 다시 로드되었다고 증명되지 않는다. Web/CLI 경로는 Desktop 경로와 다르므로 구체적 인스턴스 증거를 보존해 대조한다; 빨간 표시를 없애려고 아카이브를 옮기거나 옛 백업을 덮어쓰거나 반복 재시작하지 않는다.

이번에는 일반 파일 조작, CLI 오류 보고, 읽기 전용 진단만 조정했다; 호스트 패치, 패키지 교체 도우미, 프롬프트, 권한 정책은 바꾸지 않았다. 전체 검증은 [1.6.26](../release-notes.md#1626)을 본다.

## 1.6.29: 롤백과 네트워크

패널 롤백은 아카이브 설치로 진행하고 새 프로세스 로드를 검증하며, 실패하면 이번 작업 이전의 의존성 그래프를 복구한다. 업데이트 프록시는 플러그인 요청에만 작용하고 시스템을 바꾸지 않는다; 토큰은 GitHub API 로만 보낸다. 환경 변수는 실제 호스트 프로세스가 상속해야 한다. 옛 버전의 손상된 link 는 검증된 새 릴리스 패키지로 독립 진입점을 통해 복구한다; 사용자 설정이나 전역 캐시를 삭제하지 않는다. 제한과 실측 방법은 [유지보수 안내](maintenance-issues-34-35.md)를 본다.

## 1.6.39: 느린 네트워크 업데이트와 감사 소유자

아카이브 예산은 `PURGE_DOWNLOAD_TIMEOUT_MS` 를 쓴다(기본 180000, 범위 30000–900000); 선택 사항인 `PURGE_GH_MIRROR` 는 커뮤니티 TGZ 만 전송하며 공식 다이제스트를 쓸 수 없으면 중단한다. 컨테이너 root home 은 서비스 UID/GID 를 명확히 해야 한다; 권한을 넓히거나 전역 프록시를 바꾸지 않는다. 전체 절차, 변수, 테스트 경계는 [유지보수 안내](maintenance-issues-44-47.md)를 본다. 자동 재시작은 없다.

독립 설치기 다운로드와 네트워크 점검은 [#52 유지보수 안내](maintenance-issue-52.md)를 본다; 네트워크 실패를 설치 손상으로 오판하거나 사용자에게 설정 초기화를 요구하지 않는다.

## 1.6.41: 업데이트 상태 대조

실행 버전과 현재 profile 의 디스크 버전을 따로 대조한다; 옛 pendingVersion 은 현재 설치를 뜻하지 않는다. 미지 버전이나 읽기 실패는 계속 경고하고, 설치 실패가 성공 점검으로 가려지지 않는다. 옛 버전이 이미 멈춰 있으면 먼저 새 버전을 수동 설치하고 사용자가 직접 한 번 종료 후 재실행한다; 설정을 삭제하거나 업데이트 스위치를 바꾸거나 자동 재시작하지 않는다. 자세한 내용은 [상태 마이그레이션과 테스트 안내](maintenance-update-state.md)를 본다.

## 업데이트 채널 네트워크와 Windows 자격 증명 보호(1.6.67 / #122)

프록시 프로브, 네트워크 전송, HTTP 인증/속도 제한, 자격 증명 파일 권한을 각각 보고한다. 일시적 오류는 제한적으로만 재시도하며 인증서, 출처, 다이제스트 검증 오류를 숨길 수 없다. Windows 에서 옛 자격 증명을 처음 읽을 때 ACL 을 마이그레이션하고, 쓰기 전에 임시 디렉터리와 파일을 보호하며, 원자 교체가 실패하면 옛 파일을 보존한다. 보호 기능을 끄거나 일반 사용자 권한을 넓히거나 전역 프록시를 바꾸지 않는다. 테스트 방법과 보고자가 아직 확인하지 않은 환경은 [상세 안내](update-channel-122.md)를 본다.

## 1.6.75 설치 레이아웃, 미러와 마켓

1.6.75 는 유지보수자가 Windows 실기 제약을 인지한 상태에서 승인해 배포했다. 수정 범위, 실제 실행 증거, Windows Defender 차단은 [#130/#132/#137 검수 기록](update-layout-130-132-137.md)을 본다. 컴포넌트 테스트나 pnpm 버전 조회 통과로 Windows 전체 설치, 마이그레이션, 롤백 통과를 대신할 수 없다. 자동 재시작, 캐시 삭제, 보호 기능 변경을 하지 않는다.
