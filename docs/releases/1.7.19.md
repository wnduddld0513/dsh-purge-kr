# 1.7.19

## 고친 문제

1.7.18 을 **서브에이전트 세션**에서 실측(11건 매트릭스)하다 발견했습니다: 모델 거부를 감지한 뒤 `nudge` 재시도의 두 번째 스트림 생성이 예외를 던지면, 그 예외가 제너레이터 밖으로 빠져나가 턴 전체가 "세션 실패"로 끝났습니다.

감사 기록에는 `refusal_retry` 만 남고 `refusal_retry_outcome` 이 없었습니다. 매트릭스를 다 돌려도 `3 retry / 0 outcome` 이었고, 세 번의 거부 모두 납품도 설명 가능한 결말도 없었습니다.

## 고친 방법

- `streamFactory(current)[Symbol.asyncIterator]()` 호출을 `try` 안으로 옮겼습니다. 첫 스트림 생성 실패는 그대로 던집니다(진짜 상류 장애입니다). 재시도 스트림 생성 실패는 강등 경로로 갑니다.
- 재시도 도중 중단(`iterator.next()` 예외)도 같은 강등 경로로 갑니다.
- 강등 경로가 하는 일은 두 가지입니다.
  1. `refusal_retry_outcome { outcome: "error", attempt, frame, chars, error }` 를 기록합니다.
  2. **직전 턴에 이미 버퍼링해 둔 거부 텍스트를 그대로 내보냅니다.** 사용자는 빈 턴이나 세션 실패 대신 "모델이 거부했다"를 보게 됩니다.
- 부작용 없는 실패는 내용을 오염시키지 않습니다. 강등은 직전 턴 버퍼만 내보내고, 잘린 재시도 출력을 섞지 않습니다.

## 함께 반영한 상류 수정

- **#249**(Akiiia) 긴 세션에서 `assembleGuard` 해제 콜백이 중복 누적되던 메모리 누수: rewriteFn 기준 WeakMap 으로 disposer 를 캐시하고, 같은 개정이 다시 등록되면 만료된 disposer 를 무시합니다.
- **#255** rc.3 의 반복 도구 hook 인식(두 가지 배치 모두 인정)과, "순수 삭제형" 패치의 적용 판정이 marker 문자열에 의존하지 않게 수정.

이 둘은 master 의 병합 커밋에서 왔고 이번 릴리스에 함께 들어갑니다. `lib/index.js` 의 양쪽 변경(assembleGuard 마무리 대 거부 재시도 hook)은 자동 병합되어 충돌이 없었고, 전체 735개 테스트가 통과했습니다.

## 추가한 회귀 테스트

- `retry stream that fails to start yields the refusal instead of throwing`
- `retry stream that breaks mid-iteration also fails open`

둘 다 다음을 단언합니다: 재시도를 실제로 시도했는가, 내보낸 것이 직전 턴 텍스트인가, `audit.jsonl` 에 `"outcome":"error"` 가 있는가.

## 알려진 한계

- 서술형 거부("이건 안 합니다. 방어 관점에서 설명하면……")는 여전히 `looksLikeRefusal` 에 걸리지 않으므로 재시도도 감사 기록도 발생하지 않습니다. 검출 공백이며 이번 버전에서 다루지 않았습니다.
- 소설 프레임에서 3/3 이 모두 산출물을 내는 것은 그대로입니다(1.7.16 부터 동일). 이번 버전은 이 면을 건드리지 않습니다.

## 실기 검증 후 덧붙인 두 가지

- **재시도는 `ctx.reflect.get("llm", false)` 로 서비스를 가져옵니다**: 플러그인이 `inject: ["llm"]` 을 선언하지 않아 `ctx.llm` 을 그냥 읽으면 `cannot get property "llm" without inject` 를 던집니다. 비엄격 조회는 서비스가 없을 때 undefined 를 돌려주므로 fail-open 으로 자연스럽게 물러납니다.
- **거부 검출에 동사를 보강하고 코퍼스 회귀를 추가했습니다**: 실기에서 두 번 연속 놓쳤습니다("我不接", "이 작업의 착지점은 받지 않는다"). 실제 표본으로 빈틈을 찾는 방식은 지속 가능하지 않으므로 `test/refusal-corpus.test.mjs` 를 추가했습니다. 실제 거부 표현 49건 + 일반 기술 텍스트 12건 + 알려진 오탐 3건으로, 양성은 100% 적중하고 음성은 0건 오판을 단언합니다. 영어 규칙도 조였습니다(`I can't compile` 은 더 이상 오판하지 않고, `I can't help` 는 계속 적중).
