# 업데이트 검사와 자동 설치

유지보수 영역에는 독립 스위치 두 개가 있습니다: `autoCheck`(기본 true)와 `autoInstall`(기본 false, 옛 `autoUpdateOnStart=true` 가 있으면 그 선호를 유지합니다). 검사 기동 지연은 30초이고, 간격 `intervalHours` 는 1–168 시간 정수이며 기본값은 6 입니다.

검사를 끄면 설치가 멈추지만 설치 선호는 비우지 않습니다. 두 항목은 `autoApplyOnStart` 와 무관합니다. 설정은 `$DSH_HOME/dsh-purge/update-preferences.json` 에 저장하며, 기본값을 읽을 때 마이그레이션 파일을 쓰지 않습니다. 옛 profile, 프롬프트, 다른 플러그인 설정, 채널 고정은 바뀌지 않습니다.

자동 설치는 고정되지 않은 커뮤니티 정식 버전만 대상으로 하며, SHA256 검증, 백업, 설치 실패 복구를 그대로 씁니다. 네트워크 검사가 돌아온 뒤 스위치를 다시 읽습니다. 그때 꺼져 있거나 플러그인이 제거되었으면 설치를 시작하지 않습니다. 이미 시작한 설치는 강제로 중단하지 않고 끝난 뒤 결과를 저장합니다.

`update-status.json` 은 검사 시각, 오류, 사용 가능한 버전, 재시작 대기 버전을 기록합니다. 검사가 실패했거나 만료된 캐시만 읽을 수 있으면 `hasUpdate` 는 `null` 이고 `availableVersion` 은 마지막으로 확인한 값을 유지합니다; 이번 검사의 사유는 `error` 에 남깁니다. GitHub 공식 최신 릴리스 메타데이터를 여전히 읽을 수 있으면 안내에 그 버전 번호를 따로 표시합니다; 이 정보로 설치 패키지를 확인할 수는 없습니다. 설치가 성공하면 사용자의 수동 재시작을 기다리며 다음 자동 설치를 멈춥니다; 새 프로세스가 해당 버전을 로드하면 재시작 대기 표시를 지웁니다. 업데이트 흐름에는 재시작이나 클라이언트 새로고침 동작이 없으며, 패널이 수동 재시작을 명확히 안내합니다.

알 수 없는 필드, 잘못된 간격, 손상된 선호 파일은 오류를 내며, 조용히 기본값으로 되돌려 설치하지 않습니다. 검사 실패는 다음 주기에 다시 시도하지만 최신 버전이라고 가장하지 않습니다. 버전을 고정하면 pin 을 자동으로 넘지 않습니다.

검증은 생애주기 취소, 요청 중복 제거, 스위치 끄기, 부분 업데이트, 오류 메시지와 설정 보존을 포함합니다. 실제 릴리스 패키지 설치/롤백은 기존 유지보수 테스트를 그대로 쓰며, 사용자가 작업 중인 DSH 에 자동 설치해 테스트하지는 않았습니다.
